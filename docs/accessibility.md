# War Room accessibility

The War Room (`web/`) is a static page that replays recordings. This document separates what is proven by automated tests from what was checked by hand, with the date and what was observed. Items not checked appear as pending: nothing here was assumed.

## Proven by automated tests

| What | How | Test |
|---|---|---|
| No axe violations in the conversation, gate, dialog and post-mortem | `axe-core` 4.13 over the DOM rendered in jsdom | `web/src/test/components.test.tsx` ("axe finds no violations in conversation, gate, dialog and postmortem") |
| Approval dialog: focus moves in, stays trapped, Escape closes it and returns focus | Testing Library with `user-event` (Tab, Shift+Tab, Escape) | `web/src/test/ApprovalDialog.test.tsx` ("moves focus in, traps it, closes on Escape and returns focus") |
| The dialog has a name, a description and the warning "Local simulation: no real action" | `role="dialog"`, `aria-modal`, `aria-labelledby`, `aria-describedby` | `ApprovalDialog.test.tsx` ("names itself, warns that nothing real runs and confirms the decision") |
| Tier conveyed by text and icon, not by color alone | `TierBadge` writes "Tier N", with the tier label in `title`; the SVG icon is `aria-hidden` | `components.test.tsx` ("TierBadge communicates the tier by text") |
| Literal demo mode label on every screen | `ModeBanner` with `role="status"`, always mounted by `App` | `components.test.tsx` ("ModeBanner shows the literal label"); `App.test.tsx` |
| Keyboard focus follows the action | On load or branch choice, focus goes to Step; at the gate, to the gate heading; at the end, to the post-mortem heading | `web/src/test/App.test.tsx` ("keeps keyboard focus where the action is: step button, gate and postmortem") |
| Playback does not start on its own | No autoplay; the user steps through or presses Play | `replay-engine.test.ts` ("starts empty, without autoplay"); `components.test.tsx` |
| Contrast of at least 4.5:1 on the declared pairs, in light and dark themes | Relative luminance calculation (WCAG 2.x) over the `tokens.css` values, for the 17 pairs in `web/src/styles/contrast-pairs.json` | `web/src/test/tokens-contrast.test.ts` ("every declared pair reaches 4.5:1 in light and dark themes") |
| No literal colors outside `tokens.css` | Scan of the War Room sources | `npm run check:tokens`; `tests/unit/check-tokens.unit.test.ts` |

### Why contrast is proven by its own test

In jsdom, axe's `color-contrast` rule does not work: there is no layout or computed style. So the contrast test reads the tokens straight from the CSS (`tokens.css?raw`, with `test.css: true` in `vite.config.ts`) and computes the ratio of each declared pair. A new text and background pair must be added to `contrast-pairs.json` to be covered.

### Checklist

- [x] **Keyboard-only operable.** Scenario selection, Step, Approve, Reject and the confirmation dialog worked without a mouse on all four paths, from start to post-mortem.
- [x] **375 px with no horizontal scroll.** `scrollWidth` equal to `clientWidth`. A single 343 px column, with 16 px to spare on each side.
- [x] **Layout breakpoint.** One column below 900 px and two from there up: at 1280 px, two columns. The spec asks for one column below 600 px; the 900 px breakpoint meets that and gives tablets some slack.
- [x] **Dialog.** Opens with focus on Cancel. Tab and Shift+Tab stay trapped in the dialog. Escape closes it and returns focus to Reject.
- [x] **Demo label.** "Replay of a recorded run with a scripted fake provider" visible on every screen.
- [x] **Cost approved numbers:**
  - $339.59 in monthly savings;
  - MTTR of 19.9 min;
  - 18.0 min waiting for approval (sum of the decided approvals).
- [x] **Console.** No errors.
- [x] **Defect found and fixed.** Focus was lost when the Step button became disabled (at the gate and at the end) and went to `body`. The fix moves focus to the gate heading and to the post-mortem heading, and has a test written before it. Post-mortem in `docs/incidents/0002-focus-lost-at-the-gate.md`.
- [ ] **Screen reader.** Not yet checked with VoiceOver, NVDA or any other screen reader. The structure has labeled regions (`aria-labelledby` on each panel), `aria-live="polite"` on the playback status and `role="alert"` on load errors. The spoken experience remains unchecked.
- [ ] **200% zoom and system dark theme.** Dark theme contrast is proven by test, but reading at zoom and in the dark theme was not checked by eye.
- [ ] **Reduced motion.** `base.css` turns off transitions with `prefers-reduced-motion: reduce`. There is no automated test for it (v2 backlog item 4).

## How to repeat the check

```bash
npm run web:install    # once
npm run web:demo       # generates the recordings and starts Vite
```

In the browser, without a mouse: Tab to a scenario, Enter, Step up to the gate, Tab to Approve or Reject, Enter, Tab to confirm, Enter, and Step up to the post-mortem. Repeat at 375 px wide (the browser dev tools' responsive mode) and check that no horizontal scrollbar appears.
